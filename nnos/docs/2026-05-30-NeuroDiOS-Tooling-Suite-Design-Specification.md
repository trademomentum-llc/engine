## 1. Architectural Overview

The suite is a collection of three focused, standalone deterministic utilities sharing a common library of pure analysis primitives. No shared mutable state. Each utility is invoked independently by the Kimi executor or parallel agents and produces self-contained JSON + optional human text.

**Layering (deterministic bottom-up):**
- Layer 0: Pure utility functions (hashing, bit-math, section parsing, AST walk).
- Layer 1: Three CLI entrypoint modules (one per tool).
- Layer 2: Thin shell wrappers (optional, for integration with existing *.sh scripts).
- Layer 3: Consumer agents (Live Context, Criteria Enforcement) that read the JSON packets.

No daemonization, no background threads, no persistent caches beyond explicit --cache-dir (disabled by default).

## 2. Component Design

### 2.1 Common Analysis Primitives (Internal Module: nnos_tooling_lib.py or inlined for minimal surface)

- provenance_stamp(source_paths: list[Path]) -> dict: Returns git commit, host, per-file sha256, tool version.
- compute_bit_savings(old_bits: int, new_bits: int, count: int) -> dict: Returns exact arithmetic: total_bits_saved = count * (old_bits - new_bits), bytes_saved, percentage.
- map_to_denominators(violations: list) -> list[dict]: For each finding, return the solidifying relationships (e.g., "float64 in assess_and_offset undermines #2 Budget + #8 Drift by introducing non-deterministic rounding").
- validate_8_denom_coverage(justification: list[str]) -> bool: Simple whitelist check against the canonical 8 names.

All functions are pure or read-only on the filesystem.

### 2.2 Efficiency Mandate Auditor — Design

**Entry:** scripts/efficiency_mandate_auditor.py

**Inputs:** 
- --target (file or directory, default neurobalance/)
- --language (py|cpp|auto)
- --strict (fail on any float in hot path)

**Core Algorithm (deterministic):**
1. Walk target with pathlib (sorted order for reproducibility).
2. For Python: use ast.parse + custom NodeVisitor that tracks function context. Flag:
   - ast.Constant with float value in function whose name matches HOT_PATH_PATTERNS.
   - ast.Compare where left/right are float literals or names typed as float in annotations.
   - Assignments of float literals to fields of DenominatorReading/OffsetAction.
3. For C/C++: regex on numeric literals with decimal point or 'f'/'F' suffix inside function bodies (conservative; no full parser in v1). Later phases may add tree-sitter if required.
4. For each violation: compute line number, surrounding context (3 lines), estimated instances per cycle (heuristic from call graph — static for v1), bit savings using compute_bit_savings(64, 8 or 16, instances).
5. Aggregate: total_potential_savings_bits, ranked list of files by waste.
6. Remediation: generate unified diff that replaces literal and updates type where safe (e.g., 0.45 -> Intensity8(115) with comment containing the scaling derivation: 0.45 * 255 ≈ 115).

**Hot Path Definition (hard-coded, justified by audit in Chained §8):** 
["assess_and_offset", "generate_uplift_opportunities", "recommend", "update_denominators", "apply_offset"]

**Output Schema:** See Technical Spec.

**Safety:** --apply-safe performs in-place edit only after writing <target>.bak-YYYYMMDD-HHMMSS and appending to scripts/auditor_audit.log with full before/after + provenance.

### 2.3 Binary Footprint Analyzer — Design

**Entry:** scripts/binary_footprint_analyzer.py

**Inputs:**
- --binary-dir (default build/)
- --include-kernel (also scan neurodios/jasterish-microkernel/ if artifacts present)
- --arch-filter (x86_64|aarch64|arm64|all)

**Core Algorithm:**
1. Discover candidates: glob for executable files + *.bin + *.elf. Filter by `file` magic or shebang.
2. For each:
   - Run `size -A <bin>` (or `size -m` on Darwin) → parse text/data/bss.
   - Run `readelf -S -W` or `otool -l` → extract section headers, flags, sizes.
   - Run `nm -S --size-sort` or equivalent → top 20 largest symbols (flag any > 128 bytes in .data that look like tables).
   - Compute stripped_sha = sha256( strip -o /tmp/stripped <bin> && cat /tmp/stripped )
   - Section vector hash for drift comparison.
3. Oversized detection heuristics (justified by Efficiency Mandate):
   - Any .data symbol > 64 bytes that is not a lookup table or string table.
   - Immediate values in disassembly wider than 16 bits used in comparison/branch paths (via objdump -d | grep -E 'cmp|test|mov.*0x[0-9a-f]{5,}').
4. Reproducibility score: 1.0 if stripped_sha matches prior golden (if supplied), else 0.0 + delta report.
5. Recommendations generated by rule table:
   - If debug symbols present: "Apply strip + -s linker flag (Phase 2)".
   - If large .data: "Promote constants to .rodata or embed as immediates (8/16-bit)".
   - Cross-arch note for TP-HCF.

**Integration:** Writes companion <binary>.footprint.json next to each analyzed binary and a master report. The existing binary_drift_check.sh can consume the section hashes.

### 2.4 Chained Truth Maintainer — Design

**Entry:** scripts/chained_source_maintainer.py

**Inputs:**
- --canonical-root (default engine/nnos)
- --apps-root (optional, for dual-root)
- --update-binding (dry-run by default; with --apply-safe writes to Chained file)

**Core Algorithm (read-only unless flagged):**
1. Load canonical Chained_Source_of_Truth_Kimi_Binding.md and Minimal_Context variant.
2. Regex + section parser for:
   - All occurrences of "5 Validated Denominators" or "five denominators".
   - References to Binary-Optimization-Plan.md "Current Execution Status".
   - Git commit hashes and version strings.
3. Walk docs/ for any .md containing legacy language; classify each as HISTORICAL or ACTIVE.
4. Compare declared Phase status in Binary Opt Plan against observable state (presence of jstar* artifacts, section header presence via file + readelf).
5. Produce:
   - Coherence matrix (table of documents vs 8 denominators + Efficiency).
   - Drift report: any binding section whose content SHA differs from last recorded in the binding's own §7.
   - Actionable packet for Live Context agent.

**Output:** Always includes "binding_coherence_version": "1.3.0" and a "recommended_binding_update" object when discrepancies exist.

## 3. Data Flow & Contracts

All tools follow identical top-level contract (see Technical Spec for JSON Schema sketch):

```json
{
  "meta": { "tool": "...", "version": "1.0.0", "git_commit": "...", "analyzed_paths": [...], "denominator_justification": [ { "denom": 2, "mechanism": "...", "uplift": "..." } ] },
  "summary": { ... },
  "findings": [ ... ],
  "recommendations": [ ... ],
  "math_proofs": [ { "statement": "Replacing 14 float64 scalars with Intensity8 yields 14*(64-8)=784 bits saved per evaluation cycle", "derivation": "count * (64 - 8)" } ]
}
```

Exit semantics and safety model as per Requirements NFR-04.

## 4. Interaction with Existing Artifacts

- Extends (does not replace) generate_provenance_manifest.sh and binary_drift_check.sh.
- Auditor output can be fed into the Improvement Ledger as a "compounding micro-improvement" (denom #3 + #5).
- Maintainer output is the canonical feed for Live Context Maintenance Agent updates to Chained binding §7.

## 5. Error Handling & Edge Cases

- Missing binutils: graceful degradation with explicit "tool unavailable on this host" + fallback pure-Python size estimation where possible.
- Non-UTF8 sources: skip with warning, record in meta.skipped.
- Zero findings: still emit full meta + empty findings array (never silent success without provenance).

## 6. Evolution Path

Future phases (post Phase 1 Binary Opt stabilization):
- Add Jasterish source scanner once compiler.jstr is restored and stable.
- Tree-sitter or libclang for precise C++ type inference.
- Integration as CMake custom target for CI drift gates.
